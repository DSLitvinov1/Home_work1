# Tempo — учёт рабочего времени

Мини-приложение для тестового задания Falcon AI / Falcon Jobster. Создано с нуля; все примеры сотрудников в тестах **вымышленные**.

## Возможности

- Добавление сотрудников с проверкой имени.
- Запуск таймера с обязательным описанием задачи (2–500 символов).
- Остановка и просмотр активных таймеров; у одного сотрудника одновременно может работать только один таймер.
- Сводка по сотрудникам, раскрываемые задачи и суммарное время за **выбранные даты**, включая пересекающие границы периода записи и текущие сессии.
- Данные сохраняются в **SQLite** на диске даже после остановки и повторного запуска сервера. Время считается на сервере, поэтому закрытие вкладки не останавливает таймер.
- Адаптивный интерфейс для мобильных устройств и компьютеров.

## Как запустить

Нужен только **Python 3.10+**, установка пакетов и платные сервисы не требуются.

```bash
python app.py
```

Откройте **http://127.0.0.1:8000**. На некоторых системах команда запуска называется `python3 app.py`.

По умолчанию данные сохраняются в `data/tracker.sqlite3`; эта папка исключена из Git. Для отдельной базы можно задать переменную `TRACKER_DB_PATH` с путём к файлу. Порт настраивается через `PORT`, интерфейс прослушивания — `HOST` (по умолчанию только localhost для безопасного локального запуска).

Чтобы попробовать: добавьте вымышленного сотрудника, выберите его, укажите задачу, нажмите «Запустить таймер», затем «Стоп». Откройте детали сотрудника в отчёте. Перезапустите сервер — данные и ранее запущенные таймеры останутся.

## Проверки

```bash
python -m unittest discover -s tests -v
```

В `tests/test_app.py` проверяются:

1. Добавление сотрудника, запуск и остановка таймера, просмотр записи и отчёта.
2. **Повторный запуск** — второй активный таймер блокируется с HTTP 409; после остановки запуск снова доступен.
3. **Пустой отчёт** — работает как без сотрудников, так и за период без записей.
4. **Перезапуск сервера** — сотрудники и незакрытый таймер читаются из SQLite после старта нового экземпляра.
5. **Конкурентный запуск** — из восьми одновременных запросов только один создаёт таймер.
6. **Границы периода** — продолжительная сессия учитывается лишь внутри выбранного диапазона.
7. Ошибки валидации и доставка HTML/JavaScript.

Тесты запускают реальный HTTP-сервер на случайном локальном порту и используют отдельную временную БД: тестовые данные не загрязняют приложение.

## Технологии и устройство

- **Python 3 + `http.server`** — небольшой HTTP API без сторонних зависимостей.
- **SQLite** — постоянное хранение с ограничениями базы и уникальным частичным индексом для активного таймера.
- **Vanilla JavaScript + CSS + HTML** — интерфейс без сборщика и фреймворка.
- **`unittest`** — интеграционные и регрессионные тесты.

Код организован в `app.py` (хранилище, API, запуск), `static/` (страница, стили, логика интерфейса), `tests/` (проверки). Сервер работает со временем в миллисекундах Unix UTC; браузер переводит даты отчёта из местного часового пояса в UTC. При расчёте учитывается пересечение записей с границами интервала `[начало, конец)`.

Данные не передаются в сторонние сервисы. Приложение предназначено для тестового задания / локального использования; авторизация по ТЗ отсутствует. При размещении в открытом интернете нужно добавить аутентификацию, TLS и ограничения доступа.

## Применение ИИ

Для проектирования, разработки, ревизии и документации использован **OpenAI ChatGPT (GPT-6)**. ИИ применялся не как генератор одной страницы, а как помощник по разработке полного сценария: API, SQLite, фронтенд, тестовые случаи и проверка ошибок. Внешние ИИ API в приложении не используются.

Примеры запросов, сформулированных при работе:

> «Спроектируй минимальный трекер рабочего времени с отдельными сотрудниками и SQLite. Сделай так, чтобы закрытие вкладки не останавливало учёт».

> «Защити запуск таймера от параллельных запросов и повторного запуска для одного сотрудника».

> «Добавь интеграционные тесты на пустой отчёт, повторный запуск, сохранение после перезапуска сервера и неверные параметры».

> «Проверь, корректно ли суммируются записи, которые начались до выбранного периода и закончились во время него».

> «Сделай адаптивный интерфейс без сторонних библиотек и не вставляй произвольный текст пользователя через innerHTML».

### Что обнаружено и исправлено при проверке

- **Незакрытые SQLite-подключения.** Первая версия использовала `with sqlite3.connect(...)`, что управляет транзакцией, но не закрывает соединение. Тестовый прогон выявил `ResourceWarning`; переход на `contextlib.closing` и контроль транзакции устранил предупреждение.
- **Риск двух таймеров при одновременном нажатии/запросе.** Проверка только на фронтенде недостаточна; добавлены `BEGIN IMMEDIATE` и уникальный частичный индекс в SQLite. Проверяется тестом на восемь одновременных запросов.
- **Неточная сумма для записей за пределами отчёта.** Время рассчитывается по пересечению с выбранным периодом; будущие секунды активной сессии не учитываются.
- **Опасное отображение текста задачи.** Для имён и описаний задач используются DOM-элементы и `textContent`, чтобы введённый текст не интерпретировался как HTML.

## Возможные расширения

Авторизация, экспорт CSV, редактирование записей и разграничение ролей намеренно не добавлены: тестовое задание их не требует.
